## Outcome, dependencies and source readiness

New exploratory episodes can retain an independently valid cited final briefing
when ONLY the optional question_renewals section is malformed or fails its exact
target/citation/proposal rules. Apply no renewals if any item fails. Preserve all
earlier receipts/history and grant no continuation authority from rejected output.
The reader explains that question assessments could not be updated, without raw
errors, additional controls or another question surface.

Reuse the same bounded final model request, typed response schema, Investigation
state, current source/read/claim/target validation and question-assessment renewal.
Opt in newly created episodes with a versioned recovery contract. Old episodes
keep their existing failure semantics. No new provider, request/retry, schema,
query, automatic episode/monitoring, questionnaire or interpretation of silence.

The complete response still obeys the existing 30,000-character limit. Malformed
JSON, extra base fields, invalid base findings/directions/uncertainties and missing
or invalid REQUIRED selected-question assessment still reject the whole summary.
Only the known optional field may be isolated; never coerce its invalid contents.
All shared source versions/rights, full public claim/read context, original query
and exact target bindings must remain current before recovery can be accepted.
Retain the complete renewal_context even for rejected optional output so later
changes hide dependent summaries and fence typed descendants. Existing worker
leases, access, replay, budget, pause/cancel and provenance boundaries stay intact.

Configured adapters and durable scripted fixtures are available. No paid/live
research, private production records, new keys, browser/preview/DOM/screenshots
or frozen 1.35/1.37 validation. Preserve Sites, Apache-2.0, nine native routes,
source rights and the 512 KiB active-backlog guard.

## Implemented contract

New episodes opt into optional-question-update-recovery/v1. The existing final
request still receives the typed optional renewal schema and one request budget.
Only when that response fails typed validation can its known question_renewals
field be removed and the complete remaining response independently validated.
Malformed JSON, non-JSON constants, oversized output, extra fields and invalid
required selected-question answers still fail. A private, non-serialized flag
records this local recovery; model output cannot set it or relax its own schema.

Within the apply transaction, shared sources/read/claims/targets and the opted-in
contract are rechecked before optional validation. Bad optional targets, citations
or proposals discard every renewal, rechecking the shared inputs before accepting
recovery. Base citation/direction/uncertainty and required selected-answer checks
still precede any persisted change. Complete renewal_context is retained even
with no optional update, preserving later source/claim/read dependency fences.
No rejected optional payload, raw error, new history or new query authority is saved.

Both readers add one quiet status beside a valid summary: question assessments
could not be updated and earlier assessments remain unchanged. Selected answers
and historical summaries reuse the same reader. Missing/legacy/invalidated briefings
have no such notice. No new action, panel, form, model phase or automatic retry.
Local checks passed; production activation is recorded below.
