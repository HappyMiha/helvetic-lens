## Outcome, dependencies and source readiness

After assessing an explicitly selected early direction, offer one existing saved
check that addresses a specific remaining limitation of that answer. Reuse the
same final briefing request, branch further_check proposals, question renewals,
source-contained saved_context, existing next_check card and explicit reply action.
No new engine, table, inference, search, questionnaire or automatic monitoring.

New episodes opt into selected-direction-next-check/v1. The final request receives
at most six current public saved-check/renewal candidates. It may select one exact
question ID and public query, and an index into its own validated direction-answer
limitations. The server supplies the actual limitation text, never invented by a
second rationale field. A choice can use a current saved proposal or a validated
further_check renewed in that same final response. Partial/conflicting/not-found
answers can have a proposed next check; possible answers do not imply more work.

Validate the complete candidates before and after inference. After independently
validated question renewals are saved, bind the choice to the exact resulting
saved context. Seal the supplied options, resulting question dependencies, answer
and chosen context in the existing direction-assessment receipt. Later source,
rights, question, answer or contract changes hide dependent output. Keep select(),
reply replay and typed ancestry on the canonical saved-context fingerprint; reader
annotation must not alter that identity. Do not rescue shared input changes.

Invalid/missing optional choice preserves the valid assessment, briefing and
renewals, with existing generic suggestion behavior and no claimed answer link.
Invalid optional assessment or renewal must independently recover as in 1.71.
No rejected raw output, private source text or internal receipt is exposed.
Existing/legacy, free-text and saved-check contracts keep their behavior.

Both clients add one short AI-labelled connection inside the existing next-check
card: the exact unresolved aspect it proposes to investigate. Reuse the existing
question, rationale, closed supporting passage and Continue this check button.
No added controls, live region, polling or duplicate summary. Reader checks the
annotation against the current assessment; denied/stale reads cannot revive it.

Current source adapters and fictional durable fixtures are available. No paid/live
or private production research, browser/preview/DOM/screenshots, new provider key
or frozen study. One agent/main, existing Sites, nine native routes, Apache-2.0.

## Implemented contract and local evidence

New selected-direction-next-check/v1 episodes supply up to six current public
saved-check/renewal candidates to the existing final request. A separate optional
choice identifies an exact existing question, exact saved/renewed query and a
limitation index in the validated selected-direction assessment. Partial, conflicting
and not-found outcomes may propose a check. No new generated rationale or query is
accepted here. The server binds the actual limitation text to the existing card.

Complete candidate state is compared before and after inference. Valid question
renewals are applied first; only a resulting currently eligible saved_context can
be selected. Supplied options, resulting question fingerprints, answer fingerprint
and chosen canonical context are sealed in the existing direction receipt. All
current source/rights/public-claim/read/ancestry guards remain. A rejected in-flight
next-check input records a persistent invalid-input state, so a paused episode
cannot fall back to an older generic suggestion before any final receipt exists.
The internal marker is omitted from projections. Changed candidates,
answer or contract invalidate dependent output. Internal receipts and rejected raw
optional output are omitted from projections. No additional model call or work.

Choice recovery is independent of direction-answer and question-renewal recovery.
An invalid/missing choice preserves valid output and ordinary suggestion behavior
without an answer link. Malformed renewals can leave a valid unchanged choice;
valid renewals survive a malformed choice or answer. Required bad output and shared
input changes retain their fail-closed behavior. Existing/legacy/free-text contracts
remain compatible. The canonical saved-check fingerprint used by select/replay and
ancestry is unchanged; the answer link is added only to the current projection.

Both readers reuse the existing card and one explicit Continue this check action.
One AI-labelled sentence names the actual remaining limitation. Reader validation
checks the current answer, index and exact text; stale or denied reads cannot
revive it. Source details remain closed. No new form, control, polling or live region.
