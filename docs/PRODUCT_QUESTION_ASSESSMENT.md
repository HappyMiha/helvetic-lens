## Outcome, dependencies and source readiness

An explicitly continued saved check should end with a concise cited assessment of
that exact question: possible answer, partial evidence, conflicting evidence or
no answer found in material read. Reuse the final briefing request, existing
Investigation state, source snapshots, typed ancestry and all-input source fences.
The assessment is an AI interpretation; it never accepts a claim or proves truth.
Keep the initial exploratory journey and legacy briefings compatible. No extra
provider phase, schema, model table, questionnaire, automatic episode or monitoring.

Only newly seeded typed continuations opt into a versioned required assessment.
Bind the question ID and text on the server; reject a mismatched model target.
Every substantive point has one or more exact citations to currently supplied
public sources, with support, counterevidence or context roles. Conflicting status
requires distinct cited passages and both supporting/counterevidence roles.
No-answer assessment cannot imply support. Preserve limitations and contrary
material; source/job/capture counts never choose the answer status. No successful
read retains the existing no-evidence path. Invalid output remains unavailable.

Both clients put the assessment first in the existing briefing. Show the chosen
question, carefully labelled AI status, short points, limitations and expandable
source passages. Keep prior understanding/findings in closed background details;
no duplicate answer card. History uses the same reader, with no actions on read.
Existing correction, reply replay, roles and separate explicit monitoring stay.

Use configured providers only. Scripted durable worker episodes establish contracts,
provenance and failures, not semantic accuracy. No paid/live research probe, private
production dossier, browser/DOM/screenshot QA, new key or frozen validation use.
