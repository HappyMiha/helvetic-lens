## C01a — internal draft persistence, 2026-09-11

Added generic `monitoring_subjects` and `monitoring_subject_revisions` tables,
registered in the existing organization-scoping policy. Migration
`f0627ab1d43e` follows `ef5169a0c32d` and only creates these tables/indexes;
legacy tables, legal CHECKs and APIs are unchanged. A composite foreign key
prevents a revision from pointing into another organization.

`helvetic_lens.monitoring_subjects` provides create, get, bounded list, revise,
bounded history and delete operations for private drafts. It validates the
MV2-069 configuration, retains Decimal values canonically, stores a payload hash,
and keeps old revisions when settings change. Returned configuration dictionaries
are copies. It has no public route, collector, Start or delivery side effect.

The caller supplies a server-authenticated user ID and owns the transaction.
Every repository call rechecks active membership in the session's organization;
each subject query/mutation additionally filters the owner. Existing administrator
membership permits draft writes; viewers may read their own records but cannot
write. Unknown roles, revoked membership and inactive users fail closed. Shared
organization administration does not grant access to another person's draft.

Create keys are unique per organization + owner. A retry with identical normalized
settings returns the same subject, including its current revision after later edits;
different settings with that original key produce a conflict. The database unique
constraint/savepoint also handles concurrent duplicate requests. Deleting a draft
deletes its key and private revision history; post-deletion replay/tombstone policy
for active monitors remains C01b/C06 work.

Edit/delete require the expected revision. A single conditional write checks owner,
organization, draft state and current revision. Edit appends its new revision in
the same transaction; stale writers cannot overwrite/delete a newer revision.
SQLite's legacy savepoint mode is handled explicitly so the caller's rollback
also rolls back a create/edit instead of accidentally retaining a released savepoint.
Active subjects cannot be changed through these draft operations.
